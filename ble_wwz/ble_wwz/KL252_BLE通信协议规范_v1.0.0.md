## 1. 概述

本文档定义 KL252 设备与 APP 之间的蓝牙低功耗（BLE）通信协议，包括 GATT 服务/特征定义、数据帧格式、命令码、音源文件传输、固件升级及错误处理机制，供 APP 开发人员与固件开发人员共同参考。

### 1.1 角色说明

通信双方遵循 GATT Client/Server 架构：

| 角色    | GATT 角色     | 职责说明                        |
| ----- | ----------- | --------------------------- |
| APP 端 | GATT Client | 主动发起连接、发送命令、传输文件数据、读取特征值    |
| 设备端   | GATT Server | 执行命令并通过 Notify 应答，主动上报电源状态（电量及充电状态）及事件 |

### 1.2 术语与缩略语

| 术语/缩写                  | 说明                                         |
| ---------------------- | ------------------------------------------ |
| BLE                    | Bluetooth Low Energy，蓝牙低功耗                 |
| GATT                   | Generic Attribute Profile，通用属性协议           |
| UUID                   | Universally Unique Identifier，通用唯一标识符      |
| MTU                    | Maximum Transmission Unit，最大传输单元           |
| Notify                 | GATT 服务端主动向客户端推送数据的机制                      |
| Write                  | 客户端向服务端写入数据（有响应）                           |
| Write Without Response | 客户端向服务端写入数据（无响应，吞吐量更高）                     |
| CRC                    | Cyclic Redundancy Check，循环冗余校验             |
| XOR                    | Exclusive OR，逐字节异或；本协议帧尾 Checksum 采用整帧 XOR |
| LE                     | Little-Endian，小端字节序                        |

### 1.3 协议架构

BLE 协议栈分层如下（从下到上）：

| 层次                       | 说明                                         |
| ------------------------ | ------------------------------------------ |
| Physical Layer (PHY)     | 2.4 GHz ISM 频段，支持 1 Mbps / 2 Mbps（BLE 5.0） |
| Link Layer (LL)          | 负责广播、连接管理、数据包收发                            |
| L2CAP                    | 逻辑链路控制和适配协议                                |
| ATT (Attribute Protocol) | 基于属性的客户端/服务端通信                             |
| GATT (Generic Attribute) | 定义服务、特征和描述符，本协议在此层实现                       |
| Application Layer        | 本文档定义的 KL252 自定义协议                         |

## 2. GATT 配置

### 2.1 连接参数

| 参数                  | 推荐值                 | 说明                                                                                          |
| ------------------- | ------------------- | ------------------------------------------------------------------------------------------- |
| Connection Interval | 15 ms – 30 ms       | 普通交互模式                                                                                      |
| Connection Interval | 7.5 ms – 15 ms      | 文件传输模式（高吞吐）                                                                                 |
| Slave Latency       | 0                   | 闹钟类设备保持低延迟                                                                                  |
| Supervision Timeout | 4000 ms             | 超时断连                                                                                        |
| MTU                 | 247 字节（协商，须连接后主动请求） | ATT 单包最大属性值 = MTU - 3 = 244 字节；音源分片 Payload = MTU - 9 = 238 字节（§3.5）；固件升级 Payload 同公式（§3.6） |

### 2.2 服务与特征定义

| 服务 / 特征               | UUID   | 属性                     | 说明                                   |
| --------------------- | ------ | ---------------------- | ------------------------------------ |
| 设备名服务                 | 0x1800 | Primary Service        | 标准通用访问服务                             |
| └ Device Name 特征      | 0x2A00 | Read, Write            | APP 读取或修改 BLE 广播名称                   |
| 命令服务                  | 0xAB00 | Primary Service        | 命令、应答、音源文件传输                         |
| └ Command 特征          | 0xAB01 | Write                  | APP → 设备，发送命令帧（有响应写入）                |
| └ Response 特征         | 0xAB02 | Notify                 | 设备 → APP，应答帧 / 事件通知帧                 |
| └ File Transfer 特征    | 0xAB03 | Write Without Response | APP → 设备，音源文件数据块（§3.5）               |
| 固件升级服务                | 0xAC00 | Primary Service        | 双 BANK 固件升级（§3.6 / §4.6）             |
| └ Upgrade Control 特征  | 0xAC01 | Write                  | APP → 设备，升级控制帧（`0x80`/`0x40`/`0x50`） |
| └ Upgrade Response 特征 | 0xAC02 | Notify                 | 设备 → APP，升级应答帧                       |
| └ Upgrade Data 特征     | 0xAC03 | Write Without Response | APP → 设备，升级数据帧（UpCmd `0x30`）         |
| 电池服务                  | 0x180F | Primary Service        | 标准电池服务 + KL252 厂商扩展                      |
| └ Battery Level 特征    | 0x2A19 | Read, Notify           | 标准电量百分比 0~100（单字节，兼容通用 BLE 工具）          |
| └ Power Status 特征     | 0xFF01 | Read, Notify           | **APP 主通道**：电量 + 充电状态（2 字节，见 §7.1.2）   |

### 2.3 CCCD 配置要求

使用 Notify 特征前，APP 须先写入对应的 Client Characteristic Configuration Descriptor（CCCD）以开启通知：

| 特征                       | CCCD UUID | APP 写入值           |
| ------------------------ | --------- | ----------------- |
| Response（0xAB02）         | 0x2902    | 0x0001（启用 Notify） |
| Upgrade Response（0xAC02） | 0x2902    | 0x0001（启用 Notify） |
| Battery Level（0x2A19）    | 0x2902    | 0x0001（启用 Notify） |
| Power Status（0xFF01）     | 0x2902    | 0x0001（启用 Notify） |

## 3. 数据帧格式

所有数值均采用小端字节序（Little-Endian），除非另有说明。最大帧长度受 MTU 限制，默认 MTU = 23 字节，协商后可达 247 字节。

### 3.0 全局帧头与异或校验

除 §7.1 标准电池特征（0x2A19）单字节读值、电源状态特征（0xFF01）双字节读值及 CCCD 写入（`0x0001`）外，本协议定义的**全部 BLE 数据帧**——名称修改帧、命令帧、应答帧、事件通知帧、文件数据块、固件升级帧（§3.6）——均统一采用下列封装：

| 字节偏移    | 字段           | 长度   | 说明                        |
| ------- | ------------ | ---- | ------------------------- |
| Byte 0  | FrameHeader0 | 1 字节 | 固定值 `0xA5`                |
| Byte 1  | FrameHeader1 | 1 字节 | 固定值 `0x5A`                |
| Byte 2~ | 帧负载          | 可变   | 各帧类型字段，顺序与长度规则见 §3.1~§3.6 |
| 末字节     | Checksum     | 1 字节 | 整帧异或校验，计算规则见下             |

**异或校验规则：** 校验字节 = 从帧头第一个字节（`0xA5`）开始，到负载最后一字节为止，所有字节逐位异或（XOR）运算的结果。发送方在负载末尾追加该字节；接收方对整帧（含帧头、不含校验字节）重算 XOR，结果须与末字节一致，否则丢弃该帧。

完整帧长度 = **2（帧头）+ 负载长度 + 1（校验）**。下文表格中「Byte 偏移」均指**完整帧内**的全局偏移。

### 3.1 BLE 名称修改帧（APP → 设备，Write to 0x2A00）

| 字节偏移       | 字段          | 长度   | 说明                          |
| ---------- | ----------- | ---- | --------------------------- |
| Byte 0~1   | FrameHeader | 2 字节 | 固定 `0xA5 0x5A`              |
| Byte 2     | CmdID       | 1 字节 | 固定值 0x55，名称修改命令标识           |
| Byte 3     | Seq         | 1 字节 | 序列号 0x00~ 0xFF，用于匹配应答帧      |
| Byte 4     | DataLen     | 1 字节 | 负载长度 n（1~20），即 BLE 名称字节数    |
| Byte 5~4+n | Data        | n 字节 | UTF-8 编码的 BLE 广播名称，最大 20 字节 |
| 末字节        | Checksum    | 1 字节 | 整帧 XOR 校验                   |

**示例：** 改名 `KL252` → `A5 5A 55 00 05 4B 4C 32 35 32 9D`；预期应答 → `A5 5A 00 00 55 00 AA`

### 3.2 命令帧（APP → 设备，Write to 0xAB01）

| 字节偏移       | 字段          | 长度   | 说明                                     |
| ---------- | ----------- | ---- | -------------------------------------- |
| Byte 0~1   | FrameHeader | 2 字节 | 固定 `0xA5 0x5A`                         |
| Byte 2     | CmdID       | 1 字节 | 命令码，见第 4 节                             |
| Byte 3     | Seq         | 1 字节 | 序列号 0x00~ 0xFF，单调递增，用于与应答帧匹配           |
| Byte 4     | DataLen     | 1 字节 | 负载长度 n，即 Byte 5 起的字节数（0~238，MTU=247 时） |
| Byte 5~4+n | Data        | n 字节 | 命令负载，格式依 CmdID 不同而异（见第 4 节）            |
| 末字节        | Checksum    | 1 字节 | 整帧 XOR 校验                              |

### 3.3 应答帧（设备 → APP，Notify from 0xAB02）

| 字节偏移     | 字段          | 长度   | 说明                     |
| -------- | ----------- | ---- | ---------------------- |
| Byte 0~1 | FrameHeader | 2 字节 | 固定 `0xA5 0x5A`         |
| Byte 2   | RspType     | 1 字节 | 固定值 0x00，标识本帧为命令应答帧    |
| Byte 3   | Seq         | 1 字节 | 对应命令帧的 Seq，用于请求-应答匹配   |
| Byte 4   | CmdID       | 1 字节 | 对应命令帧的 CmdID           |
| Byte 5   | Result      | 1 字节 | 执行结果码，见第 6.1 节         |
| Byte 6~  | Data        | 可变   | 可选附加数据，由具体命令定义（见第 4 节） |
| 末字节      | Checksum    | 1 字节 | 整帧 XOR 校验              |

**全文应答 hex 说明约定**：各「预期应答」及带偏移解析的表格中，**Byte 0~1** 为帧头，**Byte 2~5** 为应答公共头（`RspType` / `Seq` / `CmdID` / `Result`）；「应答 Data 偏移」从 **Byte 6** 起计。每条示例完整 hex 已含帧头与校验字节。

> **例外：** `0xAC02` Upgrade Response 的 Notify **不适用**本节格式，须按 §3.6 升级帧解析（无 `RspType`/`Result` 字段）。

### 3.4 事件通知帧（设备 → APP，Notify from 0xAB02）

设备主动上报事件时使用本帧格式，与应答帧通过 RspType 字段区分。

| 字节偏移       | 字段          | 长度   | 说明                        |
| ---------- | ----------- | ---- | ------------------------- |
| Byte 0~1   | FrameHeader | 2 字节 | 固定 `0xA5 0x5A`            |
| Byte 2     | RspType     | 1 字节 | 固定值 0x01，标识本帧为事件通知帧       |
| Byte 3     | 0xFF        | 1 字节 | 固定值 0xFF，表示非命令应答（无对应 Seq） |
| Byte 4     | EventID     | 1 字节 | 事件码，见第 6.2 节              |
| Byte 5     | DataLen     | 1 字节 | 事件数据长度 m（字节数）             |
| Byte 6~5+m | Data        | m 字节 | 事件负载，内容由 EventID 定义       |
| 末字节        | Checksum    | 1 字节 | 整帧 XOR 校验                 |

### 3.5 文件数据块（APP → 设备，Write Without Response to 0xAB03）

音源文件传输时 APP 将 `.mp3` 等音频文件分割为固定大小的数据块，逐包写入 `0xAB03`。

| 字节偏移     | 字段          | 长度   | 说明                       |
| -------- | ----------- | ---- | ------------------------ |
| Byte 0~1 | FrameHeader | 2 字节 | 固定 `0xA5 0x5A`           |
| Byte 2   | 标识符         | 1 字节 | 固定值 0x00，区分文件数据块与命令帧     |
| Byte 3~4 | PacketIndex | 2 字节 | 包序号（小端），从 0x0000 开始，每包递增 |
| Byte 5~  | Payload     | n 字节 | 文件数据片段，见下方 Payload 长度公式  |
| 末字节      | Checksum    | 1 字节 | 整帧 XOR 校验                |

**Payload 长度公式：**

`PayloadMax = (ATT_MTU - 3) - 6 = ATT_MTU - 9`

其中 `(ATT_MTU - 3)` 为单次 Write 可写入的最大属性值长度；`-6` 为全局帧头 2B + 分片头（标识符 1B + PacketIndex 2B）+ 校验 1B。MTU=247 时 **PayloadMax=238**。末包允许 `n < PayloadMax`，禁止填充补齐。

说明：Write Without Response 无 ATT 层应答，传输速率更高；丢包由 §5.2 窗口确认机制补偿。

**帧格式：** `A5 5A 00 [Index LE 2B] [Payload ≤238B] [Checksum]`

### 3.6 固件升级帧（APP ↔ 设备，0xAC01 / 0xAC02 / 0xAC03）

固件升级采用**双 BANK**协议，通过 §2.2 固件升级服务（`0xAC00`）独立特征收发。帧结构在 §3.0 全局封装之上，业务负载固定 **ControlWord = `0x22`**：

| 字节偏移                | 字段          | 长度   | 说明                                            |
| ------------------- | ----------- | ---- | --------------------------------------------- |
| Byte 0~1            | FrameHeader | 2 字节 | 固定 `0xA5 0x5A`                                |
| Byte 2              | ControlWord | 1 字节 | 固定 `0x22`                                     |
| Byte 3              | FrameLen    | 1 字节 | 数据段长度 = `UpCmd(1B) + Data(NB) + Checksum(1B)` |
| Byte 4              | UpCmd       | 1 字节 | 升级命令码，见 §4.6                                  |
| Byte 5~(3+FrameLen) | Data        | N 字节 | 命令负载（N = FrameLen − 2）                        |
| Byte (3+FrameLen)   | Checksum    | 1 字节 | 对 Byte 0 ~ Byte (2+FrameLen) 逐字节 XOR          |

```text
FrameLen = 1 + N + 1          // UpCmd(1) + Data(N) + Checksum(1)
完整帧长度 = 4 + FrameLen        // 帧头(2) + ControlWord(1) + FrameLen 字段(1) + 数据段
Data 长度 N = FrameLen − 2
```

**`0xAC02` 应答帧格式：** APP 写入 `0xAC01`/`0xAC03` 与设备经 `0xAC02` Notify 的应答，**均采用本节同一帧结构**（`A5 5A` + `ControlWord 0x22` + `FrameLen` + `UpCmd` + Data + Checksum）。**不是** §3.3 命令应答帧（无 `RspType`/`Seq`/`CmdID`/`Result`）。解析 `0xAC02` 时以 **Byte 4 的 UpCmd** 区分消息类型，Data 从 Byte 5 起；**不得**复用 `0xAB02` 的应答解析器。

| 特征                        | 属性                     | 方向       | 承载 UpCmd                                  |
| ------------------------- | ---------------------- | -------- | ----------------------------------------- |
| `0xAC01` Upgrade Control  | Write                  | APP → 设备 | `0x80` 握手、`0x40` 结束、`0x50` 查询状态           |
| `0xAC02` Upgrade Response | Notify                 | 设备 → APP | `0x81`/`0x82`/`0x31`/`0x32`/`0x41`/`0x51` |
| `0xAC03` Upgrade Data     | Write Without Response | APP → 设备 | `0x30` 固件数据                               |

升级数据 Payload 长度：`UpgradePayloadMax = ATT_MTU - 9`（MTU=247 时为 **238**），公式与 §3.5 一致，但分片头为 ControlWord+FrameLen+UpCmd 而非 PacketIndex。

## 4. 命令码详细定义

命令码（CmdID）按**功能模块分段**分配（高 4 位为模块号），各段内预留连续空号，便于版本演进时在本模块内扩展，无需在全局末尾追加。

### 4.0 CmdID 分段规划

| 段号  | CmdID 范围        | 模块    | 已用             | 预留             |
| --- | --------------- | ----- | -------------- | -------------- |
| 1   | `0x01` ~ `0x1F` | 闹钟与例程 | `0x01`~ `0x07` | `0x08`~ `0x1F` |
| 2   | `0x20` ~ `0x2F` | 系统与来电 | `0x20`~ `0x25` | `0x26`~ `0x2F` |
| 3   | `0x30`~ `0x3F`  | 设备与固件 | `0x30`/`0x31`  | `0x32`~ `0x3F` |
| 4   | `0x40`~ `0x4F`  | 音源与存储 | `0x40`~ `0x46` | `0x47`~ `0x4F` |
| 5   | `0x50`~ `0x5F`  | 文件传输  | `0x50`~ `0x54` | `0x55`~ `0x5F` |
| —   | `0x60`~ `0xFE`  | 全局预留  | —              | 新模块或跨模块能力      |
| —   | `0x00`          | 无效    | 不得作为 CmdID     | —              |

### 4.1 闹钟与例程（CmdID `0x01`~ `0x1F`）

支持两种配置类型：

| AlarmType | 名称   | 说明                                                        |
| --------- | ---- | --------------------------------------------------------- |
| `0x00`    | 例程   | **基础设置**（全局一份，`0x05`）+ **我的例程**（按 AlarmID，`0x01` 仅写时刻与周期） |
| `0x01`    | 其他闹钟 | 独立闹钟，含激活期、唤醒期两段子时期；受 **Alarms 全局开关**（`0x06`）约束            |

固件内部可按两个触发时刻调度例程，但对 APP 仅暴露为一个 `AlarmID` 记录。

#### 4.1.1 例程：基础设置与我的例程

例程（`AlarmType=0x00`）在协议层拆为两层，与 APP「Schedule → 基础设置 / 我的定时」一致：

| 层级   | 命令                       | 作用域             | 内容                                                            |
| ---- | ------------------------ | --------------- | ------------------------------------------------------------- |
| 基础设置 | `0x05`                   | 设备全局唯一一份        | 睡眠提醒音源/音量/时长；起床提示期/激活期/唤醒期/锁定期（各期的开关、MusicID、Volume、Duration） |
| 我的例程 | `0x01`（`AlarmType=0x00`） | 每条 `AlarmID` 一条 | 睡眠段、起床段各自的 **Enable、时刻、WeekMask**（不含音源与音量）                    |

**关联规则：**

1. 设备持久化一份例程基础设置；所有 `AlarmType=0x00` 条目在触发时均使用该基础设置中的音源/音量/时长。
2. **设备出厂须预置一份有效的基础设置**（见下表「出厂默认值」），首次上电、恢复出厂（`0x31`）后均须立即可用；**APP 不下发 `0x05` 时，例程仍可按预置音源/音量/时长正常触发**。
3. APP 修改基础设置并成功收到 `0x05` 应答后，**无须**对每条例程重发 `0x01`；固件须立即将新基础设置应用于全部已存在的例程（不改变各条目的时刻与 WeekMask）。
4. `AlarmType=0x01` 的其他闹钟 **不** 使用 `0x05`，各闹钟音源/音量/子时期仍由 `0x01` 单条配置。

**出厂默认基础设置（设备预置，与 §4.1 命令 `0x05` 示例一致）**

| 字段 / 子时期 | 出厂默认值                                              |
| -------- | -------------------------------------------------- |
| 目标时长     | 60 * 8 = 480 min                                   |
| 睡眠提醒     | 开启；MusicID=100，Volume=80，Duration=45 min           |
| 提示期      | 开启；MusicID=100，Volume=80，Duration=5 min            |
| 激活期      | 开启；MusicID=100，Volume=80，Duration=5 min            |
| 唤醒期      | 开启；MusicID=100，Volume=80，Duration=5 min            |
| 锁定期      | 关闭；MusicID=100，Volume=80，Duration=5 min（状态=0，参数保留） |

固件须在 Flash/NVM 中持久化该配置；`0x05` 查询在未收到 APP 设置命令时，应返回上述出厂默认值（或用户曾通过 APP 修改后的当前值）。

**基础设置块（38 字节，用于 `0x05`）**

| 字段   | 长度  | 说明                                             |
| ---- | --- | ---------------------------------------------- |
| 目标时长 | 2 B | 目标睡眠时长，单位：分钟                                   |
| 睡眠提醒 | 8 B | 状态(1B)、MusicID(4B)、Volume(1B)、**Duration(2B)** |
| 提示期  | 7 B | 子时期块                                           |
| 激活期  | 7 B | 子时期块                                           |
| 唤醒期  | 7 B | 子时期块                                           |
| 锁定期  | 7 B | 子时期块                                           |

子时期块格式见下文；起床四期默认：提示/激活/唤醒开启，锁定期关闭，各期 Duration=5min。
**子时期块（7 字节 × N，用于 `0x05` 起床四期、`0x01` 其他闹钟两期）**

| 字段       | 长度   | 类型        | 说明                       |
| -------- | ---- | --------- | ------------------------ |
| 状态       | 1 字节 | uint8     | `0x00`=关闭  `0x01`=开启     |
| MusicID  | 4 字节 | uint32 LE | 音源 ID，范围 100~999999      |
| Volume   | 1 字节 | uint8     | 音量，范围 1~100（默认 80）       |
| Duration | 1 字节 | uint8     | 时长，单位分钟，范围 1~60（默认 5min） |

#### 命令 0x01 — 新增/修改闹钟

APP 通过本命令新增或修改配置。 `AlarmID` 由 APP 生成；设备中不存在该 ID 则新增，否则覆盖修改。

**原子性（AlarmType=0x00）：** 设备须在单次命令内同时校验并持久化睡眠段与起床段的**调度块**；任一段非法或写入失败时，返回 `Result≠0x00`，**不得**出现仅更新其中一段的中间态。

**负载公共头（3 + NameLen 字节，NameLen 范围 0~30）**

| 字段        | 长度         | 类型    | 说明                     |
| --------- | ---------- | ----- | ---------------------- |
| AlarmType | 1 字节       | uint8 | `0x00`=例程  `0x01`=其他闹钟 |
| AlarmID   | 1 字节       | uint8 | 闹钟唯一标识，0x01~ 0xFF      |
| NameLen   | 1 字节       | uint8 | 闹钟名称长度，0~30            |
| Name      | NameLen 字节 | bytes | UTF-8 编码闹钟名称，最大 30 字节  |

**调度块（4 字节，睡眠段/起床段/其他闹钟各含一组）**

| 字段       | 长度   | 类型    | 说明                                                          |
| -------- | ---- | ----- | ----------------------------------------------------------- |
| Enable   | 1 字节 | uint8 | `0x00`=关闭  `0x01`=开启（默认开启）                                  |
| Hour     | 1 字节 | uint8 | 启动时间-小时，范围 0x00~ 0x17（0~23）                                 |
| Minute   | 1 字节 | uint8 | 启动时间-分钟，范围 0x00~ 0x3B（0~59）                                 |
| WeekMask | 1 字节 | uint8 | 周期位掩码，定义见 §8.2；`0x80`=从不（单次）；`0x01`~ `0x7F` 且 bit7=0 为按星期重复 |

**AlarmType=0x00 我的例程负载（11 + NameLen 字节，NameLen=0 时最小 11 字节）**

| 段   | 长度            | 内容                                          |
| --- | ------------- | ------------------------------------------- |
| 公共头 | 3 + NameLen B | AlarmType=`0x00` + AlarmID + NameLen + Name |
| 睡眠段 | 4 B           | 调度块（Enable / Hour / Minute / WeekMask）      |
| 起床段 | 4 B           | 调度块                                         |

音源与音量由 `0x05` 基础设置提供。默认值：睡眠 22:00 每天；起床 07:00 每天。

**AlarmType=0x01 其他闹钟负载（21 + NameLen 字节，NameLen=0 时最小 21 字节）**

| 段   | 长度            | 内容                                          |
| --- | ------------- | ------------------------------------------- |
| 公共头 | 3 + NameLen B | AlarmType=`0x01` + AlarmID + NameLen + Name |
| 调度块 | 4 B           | 同前                                          |
| 子时期 | 14 B          | 激活期(7B) + 唤醒期(7B)                           |

默认启动时间 07:00，周期每天。

**示例 A：新增/修改我的例程（睡眠 22:00 / 起床 07:00，每天）**

**hex（17 字节 = 2 帧头 + 14 负载 + 1 校验，`DataLen=0x0B`，公共头 3B + 睡眠调度 4B + 起床调度 4B；本例 NameLen=0，无名称）**

`A5 5A 01 0A 0B 00 01 00 01 16 00 7F 01 07 00 7F EF`

| 偏移    | 字节            | 字段          | 解析         |
| ----- | ------------- | ----------- | ---------- |
| 0~1   | `A5 5A`       | FrameHeader | 固定帧头       |
| 2     | `01`          | CmdID       | 新增/修改闹钟    |
| 3     | `0A`          | Seq         | 10         |
| 4     | `0B`          | DataLen     | 负载 11 字节   |
| 5     | `00`          | AlarmType   | 例程         |
| 6     | `01`          | AlarmID     | 1          |
| 7     | `00`          | NameLen     | 0（无名称）     |
| 8~11  | `01 16 00 7F` | 睡眠段调度       | 开，22:00，每天 |
| 12~15 | `01 07 00 7F` | 起床段调度       | 开，07:00，每天 |
| 16    | `EF`          | Checksum    | 整帧 XOR     |

**预期应答**

`A5 5A 00 0A 01 00 F4`

---

**示例 B：新增其他闹钟（07:30 工作日，MusicID=200）**

**hex（27 字节 = 2 帧头 + 24 负载 + 1 校验，`DataLen=0x15`，公共头 3B + 调度块 4B + 两期×7B；本例 NameLen=0，无名称）**

`A5 5A 01 0C 15 01 02 00 01 07 1E 3E 01 C8 00 00 00 3C 0A 01 C8 00 00 00 3C 0A C2`

| ID  | 1 字节 | uint8 | 要删除的 AlarmID |

**示例：查询全部闹钟**

`A5 5A 03 0D 00 F1`

**应答附加数据格式：**

| 字段           | 长度   | 类型    | 说明                             |
| ------------ | ---- | ----- | ------------------------------ |

| AlarmID[0]   | 1 字节 | uint8 | AlarmID                        |
| ...          | ...  | ...   | 以此类推，每条目 2 字节                  |

#### 命令 0x04 — 查询闹钟详情

| 字段  | 长度   | 类型    | 说明           |
| --- | ---- | ----- | ------------ |
| ID  | 1 字节 | uint8 | 要查询的 AlarmID |

应答附加数据格式与 `0x01` 写入负载相同：**例程 11 + NameLen 字节**（仅我的例程调度）；**其他闹钟 21 + NameLen 字节**。例程完整生效配置 = `0x05` 基础设置 + `0x04` 本条调度。

**示例：查询 AlarmID=1 详情**

`A5 5A 04 0E 01 01 F5`

**预期应答 Data**：与上文 **示例 A** 命令负载中公共头起的部分相同；完整 Notify 帧 Byte 0~1 为帧头，Byte 2~5 为应答公共头（§3.3），Data 从 Byte 6 起。

#### 命令 0x05 — 例程基础设置 / 查询

设置或读取设备全局唯一的例程基础设置（§4.1.1）。**仅作用于 `AlarmType=0x00`。**

| 方向  | DataLen | 说明                        |
| --- | ------- | ------------------------- |
| 设置  | 38      | 写入基础设置块（38 字节，格式见 §4.1.1） |
| 查询  | 0       | 无负载，应答 Data 为 38 字节当前基础设置 |

**设备侧要求：** 出厂须预置 §4.1.1「出厂默认基础设置」；APP 未下发本命令前，例程触发须使用该预置配置。`0x31` 恢复出厂后须还原为出厂默认值。

应答：Result=0x00 成功。设置成功后固件须将新参数同步到所有已存在的例程条目。

**示例 A：设置例程基础设置（同 §4.1.1 出厂默认值）**

**hex（44 字节 = 2 帧头 + 41 负载 + 1 校验，`DataLen=0x26`，基础设置 38B）**

```text
A5 5A 05 0B 26 E0 01 01 64 00 00 00 50 2D 00 01 64 00 00 00 50 05 01 64 00 00 00 50 05 01 64 00 00 00 50 05 00 64 00 00 00 50 05 2F
```

| 偏移    | 字节           | 字段 / 子时期    | 解析                          |
| ----- | ------------ | ----------- | --------------------------- |
| 0~1   | `A5 5A`      | FrameHeader | 固定帧头                        |
| 2     | `05`         | CmdID       | 例程基础设置                      |
| 3     | `0B`         | Seq         | 11                          |
| 4     | `26`         | DataLen     | 负载 38 字节                    |
| 5~6   | `E0 01`      | 目标时长        | 480 min                     |
| 7~14  | `01 64 … 00` | 睡眠提醒        | 开，MusicID=100，Vol=80，45 min |
| 15~21 | `01 64 … 05` | 提示期         | 开，MusicID=100，Vol=80，5 min  |
| 22~28 | `01 64 … 05` | 激活期         | 开，MusicID=100，Vol=80，5 min  |
| 29~35 | `01 64 … 05` | 唤醒期         | 开，MusicID=100，Vol=80，5 min  |
| 36~42 | `00 64 … 05` | 锁定期         | 关，MusicID=100，Vol=80，5 min  |
| 43    | `2F`         | Checksum    | 整帧 XOR                      |

**预期应答**

`A5 5A 00 0B 05 00 F1`

说明：成功后设备立即将上述音源/音量/时长应用于**全部** `AlarmType=0x00` 条目，无需逐条重发 `0x01`。

**示例 B：查询例程基础设置（出厂预置 / 未收到 APP 设置时）**

`A5 5A 05 10 00 EA`

**预期应答 Data：** 38 字节基础设置块，内容与 §4.1.1「出厂默认基础设置」或最近一次成功设置一致（Result=0x00）。

#### 命令 0x06 — Alarms（AlarmType=1）全局开关 / 查询

对应 APP「Alarms」模块总开关。控制所有 `AlarmType=0x01` 其他闹钟是否允许触发响铃。

| 方向  | DataLen | 说明                 |
| --- | ------- | ------------------ |
| 设置  | 1       | 写入 `AlarmsEnable`  |
| 查询  | 0       | 无负载，应答 Data 为 1 字节 |

| 字段           | 长度   | 类型    | 说明                           |
| ------------ | ---- | ----- | ---------------------------- |
| AlarmsEnable | 1 字节 | uint8 | `0x00`=关闭全局开关  `0x01`=开启（默认） |

**行为：**

- `AlarmsEnable=0x00` 时，**所有** `AlarmType=0x01` 条目均不得响起，与各条目调度块中 `Enable` 无关（配置保留，恢复全局开关后按原 `Enable` 生效）。
- `AlarmsEnable=0x01` 时，按各其他闹钟自身的 `Enable`、时刻与 WeekMask 正常调度。
- **不影响** `AlarmType=0x00` 例程及来电提醒（`0x23`/`0x24`）。

**示例：关闭 Alarms 全局开关**

`A5 5A 06 11 01 00 E9`

**示例：查询 Alarms 全局开关**

`A5 5A 06 12 00 EB`

**预期应答（开启）**

`A5 5A 00 12 06 00 01 EA`

#### 命令 0x07 — 查询闹钟/例程运行状态

APP 发送本命令（DataLen=0），设备返回当前是否有闹钟或例程正在执行，以及正在执行的 `AlarmID` 与 **子阶段（Phase）**。

| AlarmID   | 1 字节 | uint8 | 仅 `RunState=0x01` 时有效，当前运行的 AlarmID          |
| Phase     | 1 字节 | uint8 | 仅 `RunState=0x01` 时有效，当前子阶段，取值见下表            |

**Phase 取值（`RunState=0x01`）：**

| AlarmType   | Phase  | 含义    |
| ----------- | ------ | ----- |
| `0x00` 例程   | `0x00` | 睡眠提醒段 |
| `0x00` 例程   | `0x01` | 起床提示期 |
| `0x00` 例程   | `0x02` | 起床激活期 |
| `0x00` 例程   | `0x03` | 起床唤醒期 |
| `0x00` 例程   | `0x04` | 起床锁定期 |
| `0x01` 其他闹钟 | `0x00` | 激活期   |
| `0x01` 其他闹钟 | `0x01` | 唤醒期   |

**应答 DataLen：** `RunState=0x00` 时为 1 字节；`RunState=0x01` 时为 4 字节。

**示例：查询运行状态（无运行中任务）**

`A5 5A 07 13 00 EB`

**预期应答**

`A5 5A 00 13 07 00 00 EB`

**示例：例程 AlarmID=1 正在执行起床唤醒期**

`A5 5A 07 14 00 EC`

**预期应答**

`A5 5A 00 14 07 00 01 00 01 03 EF`
**示例：其他闹钟 AlarmID=2 激活期 — 预期应答：** `A5 5A 00 15 07 00 01 01 02 00 EF`

### 4.2 系统与来电（CmdID `0x20`~ `0x2F`）

#### 命令 0x20 — 当前时间同步

设备 RTC 与移动设备日历时间对齐。建议每次 BLE 连接建立后立即发送。负载共 **7 字节**（年/月/日 + 星期 + 时/分/秒）。

| 字段     | 长度   | 类型        | 说明                                      |
| ------ | ---- | --------- | --------------------------------------- |
| Year   | 2 字节 | uint16 LE | 公历年份，范围 2000~2099（如 2026 → `0xEA 0x07`） |
| Month  | 1 字节 | uint8     | 月份，范围 0x01 ~ 0x0C（1 ~ 12）               |
| Day    | 1 字节 | uint8     | 日期，范围 0x01 ~ 0x1F（1 ~ 31）               |
| Week   | 1 字节 | uint8     | 星期，0x01=周一 … 0x07=周日（ISO 8601）          |
| Hour   | 1 字节 | uint8     | 小时，范围 0x00 ~ 0x17（0 ~ 23）               |
| Minute | 1 字节 | uint8     | 分钟，范围 0x00 ~ 0x3B（0 ~ 59）               |
| Second | 1 字节 | uint8     | 秒，范围 0x00 ~ 0x3B（0 ~ 59）                |

参数非法（如 2 月 30 日、Week 与日期不符）时设备返回 `Result=0x01`。

**示例：同步时间为 2026-06-02（周一）13:30:05**

`A5 5A 20 07 07 EA 07 06 02 01 0D 1E 05 21`

**预期应答**

`A5 5A 00 07 20 00 D8`

**示例：查询免打扰状态**

`A5 5A 00 13 25 00 01 C8`

### 4.4 音源与存储（CmdID `0x40`~ `0x4F`）

**应答附加数据格式：**

| 字段         | 长度   | 类型        | 说明                                              |
| ---------- | ---- | --------- | ----------------------------------------------- |

**示例：查询音源列表**

`A5 5A 41 13 00 AD`

**预期应答（2 个音源：ID=100、200）**

`A5 5A 00 13 41 00 02 64 00 00 00 C8 00 00 00 03`

#### 命令 0x42 — 删除音源

| 字段      | 长度   | 类型        | 说明        |
| ------- | ---- | --------- | --------- |
| MusicID | 4 字节 | uint32 LE | 要删除的音源 ID |

应答：Result=0x00 成功；Result=0x05 MusicID 不存在；Result=0x02 设备忙（如正在播放该音源且不可删除）。

`A5 5A 42 14 04 64 00 00 00 C9`

APP 发送本命令，设备按 MusicID 播放已存储音源。若当前已有播放任务，设备须先停止再切换至新音源。

| 字段      | 长度   | 类型        | 说明                      |
| ------- | ---- | --------- | ----------------------- |
| MusicID | 4 字节 | uint32 LE | 要播放的音源 ID，范围 100~999999 |

应答：Result=0x00 已开始播放；Result=0x05 MusicID 不存在。

**示例：播放 MusicID=100**

`A5 5A 43 15 04 64 00 00 00 C9`

**预期应答**

`A5 5A 00 15 43 00 A9`

#### 命令 0x44 — 暂停音乐播放

APP 发送本命令（DataLen=0，无负载），设备暂停当前由 CmdID `0x43` 发起的播放。若无此类播放任务，设备仍返回 Result=0x00。

应答：Result=0x00 已暂停或当前无 APP 播放。

**示例：暂停播放**

`A5 5A 44 16 00 AD`

**预期应答**

`A5 5A 00 16 44 00 AD`

#### 命令 0x45 — 音量设置

APP 发送本命令设置播放音量；若当前无播放任务，音量仍须保存并在下次 CmdID `0x43` 播放时生效。

| 字段     | 长度   | 类型    | 说明                 |
| ------ | ---- | ----- | ------------------ |
| Volume | 1 字节 | uint8 | 音量，范围 1~100（默认 80） |

应答：Result=0x00 成功；Result=0x01 参数错误（Volume 超出范围）。

**示例：设置音量为 80**

`A5 5A 45 17 01 50 FC`

**预期应答**

`A5 5A 00 17 45 00 AD`

#### 命令 0x46 — 查询音乐播放状态

APP 发送本命令（DataLen=0），设备返回当前音源播放状态。适用于连接后同步 UI、从后台恢复控制页，或在执行 `0x43`/`0x44`/`0x45` 后确认实际状态。

**应答附加数据格式：**

| 字段         | 长度   | 类型        | 说明                                                                      |
| ---------- | ---- | --------- | ----------------------------------------------------------------------- |
| PlayState  | 1 字节 | uint8     | `0x00`=空闲  `0x01`=播放中  `0x02`=已暂停（仅 `PlaySource=0x00` 时可能出现）            |
| PlaySource | 1 字节 | uint8     | 仅 `PlayState≠0x00` 时有效：`0x00`=APP 点播（`0x43`）  `0x01`=例程/闹钟  `0x02`=来电提醒 |
| MusicID    | 4 字节 | uint32 LE | 仅 `PlayState≠0x00` 时有效，当前播放音源 ID；无有效音源时填 `0x00000000`                   |
| Volume     | 1 字节 | uint8     | 当前音量 1~100；空闲时为 `0x45` 持久化音量，播放中为实时输出音量                                 |

**应答 Data 长度：** `PlayState=0x00` 时为 **2 字节**（`PlayState` + `Volume`）；`PlayState=0x01`/`0x02` 时为 **7 字节**（含 `PlaySource`、`MusicID`、`Volume`）。

**行为说明：**

- APP 通过 `0x43` 开始播放后，`PlaySource=0x00` 且 `PlayState=0x01`；`0x44` 暂停后为 `PlayState=0x02`，`MusicID` 保持暂停前曲目。
- 例程/闹钟、来电提醒播放时，`PlaySource` 分别为 `0x01`/`0x02`；此时 `PlayState` 仅可能为 `0x01`（无暂停态）。
- 设备播放自然结束或用户按键停止后，若再无其他音源任务，应上报 `PlayState=0x00`。

**示例：查询播放状态**

`A5 5A 46 18 00 A1`

**预期应答（空闲，Volume=80）**

`A5 5A 00 18 46 00 00 50 F1`

**预期应答（APP 点播 MusicID=100 播放中，Volume=80）**

`A5 5A 00 18 46 00 01 00 64 00 00 00 50 94`

**预期应答（APP 点播已暂停，MusicID=100，Volume=80）**

`A5 5A 00 18 46 00 02 00 64 00 00 00 50 97`

**预期应答（例程/闹钟播放中，MusicID=100，Volume=80）**

`A5 5A 00 18 46 00 01 01 64 00 00 00 50 95`

### 4.6 固件升级 — 双 BANK 协议（GATT `0xAC00`）

设备支持通过蓝牙进行固件升级。APP 发起前须先通过主协议 CmdID `0x30`（§4.3，`0xAB01`）查询当前版本。升级走 **`0xAC00` 服务及 UpCmd**，与 §4.5 音源文件传输（`0xAB00` / CmdID `0x50`~`0x53`）**通道与时序完全独立**：逐包停等应答，**不使用**主协议 EventID。互斥规则见 §5.0。

**UpCmdID 定义：**

| UpCmd  | 方向       | 特征              | 说明            |
| ------ | -------- | --------------- | ------------- |
| `0x80` | APP → 设备 | `0xAC01` Write  | 握手，携带文件总大小    |
| `0x81` | 设备 → APP | `0xAC02` Notify | 握手成功          |
| `0x82` | 设备 → APP | `0xAC02` Notify | 握手失败          |
| `0x30` | APP → 设备 | `0xAC03` WWR    | 传输固件数据片段      |
| `0x31` | 设备 → APP | `0xAC02` Notify | 数据接收成功        |
| `0x32` | 设备 → APP | `0xAC02` Notify | 数据接收失败，须重发上一包 |
| `0x40` | APP → 设备 | `0xAC01` Write  | 结束传输          |
| `0x41` | 设备 → APP | `0xAC02` Notify | 结束应答          |
| `0x50` | APP → 设备 | `0xAC01` Write  | 查询升级状态        |
| `0x51` | 设备 → APP | `0xAC02` Notify | 状态应答          |

> **命名空间说明：** 本节 **UpCmd** 运行于 GATT `0xAC00`，与主协议 **CmdID**（`0xAB01`）数值可能相同但语义不同。典型冲突：`UpCmd 0x30`=写固件数据 vs **CmdID `0x30`**=查版本；`UpCmd 0x31`=数据接收成功 vs **CmdID `0x31`**=恢复出厂；`UpCmd 0x50`/`0x51`=升级状态 vs **CmdID `0x50`/`0x51`**=音源传输。`0xAC02` 应答帧格式见 §3.6，**不得**按 §3.3 解析。

#### UpCmd `0x80` — 升级握手

| 字段       | 偏移（Data 内） | 长度   | 类型        | 说明       |
| -------- | ---------- | ---- | --------- | -------- |
| FileSize | 0          | 4 字节 | uint32 LE | 固件文件总字节数 |

FrameLen = `0x06`（= UpCmd 1 + FileSize 4 + Checksum 1）。设备擦除目标 Flash 块后回复 UpCmd `0x81`；失败回复 UpCmd `0x82`。

**示例：握手（FileSize = 102400）**

`A5 5A 22 06 80 00 90 01 00 CA`

#### UpCmd `0x81` / `0x82` — 握手应答

Data：FileSize(4B) 回显。FrameLen=`0x06`。`0x81` 成功后可发 UpCmd `0x30`；`0x82` 失败（Flash 忙、互斥等），可 500ms 后重发 `0x80`。

**示例（成功）：** `A5 5A 22 06 81 00 90 01 00 CB`；**失败：** `A5 5A 22 06 82 00 90 01 00 C8`

#### UpCmd `0x30` — 写固件数据

| 字段      | 偏移（Data 内） | 长度   | 说明                      |
| ------- | ---------- | ---- | ----------------------- |
| Payload | 0          | N 字节 | 文件连续字节；N = FrameLen − 2 |

FrameLen = `1 + N + 1`（含 UpCmd 与 Checksum），N ≤ UpgradePayloadMax（§3.6）。设备写入 **63KB FIFO** 后异步落盘；每包须等待 UpCmd `0x31`/`0x32`（`0xAC02` Notify）再发下一包。

**分包规则：**

```text
UpgradePayloadMax = ATT_MTU - 9     // MTU=247 → 238
FrameLen = 1 + PayloadLen + 1
包数 N = ⌈FileSize / UpgradePayloadMax⌉
末包 PayloadLen = FileSize - (N-1) × UpgradePayloadMax
```

末包禁止填充；须按顺序覆盖 `[0, FileSize)` 完整区间。

**示例：第 1 包（Payload 6 字节示意）**

`A5 5A 22 08 30 01 02 03 04 05 06 E2`

#### UpCmd `0x31` / `0x32` — 数据应答

| 字段     | 偏移（Data 内） | 长度   | 类型    | 说明                          |
| ------ | ---------- | ---- | ----- | --------------------------- |
| Status | 0          | 1 字节 | uint8 | `0x01`=接收成功；`0x00`=接收失败，须重发 |

FrameLen = `0x03`（= UpCmd 1 + Status 1 + Checksum 1）。

**预期应答（UpCmd `0x31`，Status=`0x01`）**

`A5 5A 22 03 31 01 EE`

**预期应答（UpCmd `0x32`，Status=`0x00`，须重发同一 Payload）**

`A5 5A 22 03 32 00 EC`

#### UpCmd `0x40` — 结束传输

| 字段      | 偏移（Data 内） | 长度   | 类型    | 说明                |
| ------- | ---------- | ---- | ----- | ----------------- |
| EndFlag | 0          | 1 字节 | uint8 | 固定填 `0x00`，表示传输结束 |

FrameLen = `0x03`（= UpCmd 1 + EndFlag 1 + Checksum 1）。APP 在全部 UpCmd `0x30` 包均获 UpCmd `0x31` 确认后发送 UpCmd `0x40`；设备完成固件落盘后通过 UpCmd `0x41` 返回结果。

**示例：结束命令**

`A5 5A 22 03 40 00 9E`

#### UpCmd `0x41` — 结束应答

| 字段     | 偏移（Data 内） | 长度   | 类型    | 说明                                                       |
| ------ | ---------- | ---- | ----- | -------------------------------------------------------- |
| Status | 0          | 1 字节 | uint8 | `0x01`=升级成功，设备约 **1 秒后自动重启**并切换 Bank；`0x00`=升级失败（如落盘不完整） |

FrameLen = `0x03`。

**预期应答（升级成功）**

`A5 5A 22 03 41 01 9E`

升级失败时 Status=`0x00`。

#### UpCmd `0x50` — 查询升级状态

无 Data 字段。FrameLen = `0x02`（= UpCmd 1 + Checksum 1）。可在握手前或升级过程中查询当前阶段。

**示例：查询命令**

`A5 5A 22 02 50 8F`

#### UpCmd `0x51` — 状态应答

| 字段           | 偏移（Data 内） | 长度   | 类型    | 说明              |
| ------------ | ---------- | ---- | ----- | --------------- |
| UpgradeState | 0          | 1 字节 | uint8 | 当前升级阶段，见下表      |
| Progress     | 1          | 1 字节 | uint8 | 进度百分比 `0`~`100` |

FrameLen = `0x04`（= UpCmd 1 + UpgradeState 1 + Progress 1 + Checksum 1）。

| UpgradeState | 含义          |
| ------------ | ----------- |
| `0x00`       | 空闲          |
| `0x01`       | 握手中         |
| `0x02`       | 数据传输中       |
| `0x03`       | 落盘处理中       |
| `0x04`       | 升级成功 / 即将重启 |
| `0x05`       | 升级失败        |

**预期应答（空闲）**

`A5 5A 22 04 51 00 00 88`

#### 完整交互时序

```text
阶段一：握手（UpCmd 命名空间，§3.6 帧）
  APP ──UpCmd 0x80 + FileSize──► 0xAC01
  APP ◄──UpCmd 0x81 / 0x82────── 0xAC02 Notify

阶段二：数据传输（停等，多次）
  APP ──UpCmd 0x30 + Payload──► 0xAC03
  APP ◄──UpCmd 0x31 / 0x32──── 0xAC02 Notify

阶段三：结束
  APP ──UpCmd 0x40────────────► 0xAC01
  APP ◄──UpCmd 0x41──────────── 0xAC02 Notify → 约 1 秒后重启
```

**时序约束：** 单次会话仅一次 UpCmd `0x80`；每包 UpCmd `0x30` 须等 UpCmd `0x31`（UpCmd `0x32` 则重发）；不支持断点续传；与音源文件传输**不可并行**（见 §5.0）。FIFO 满时设备可能丢弃新帧，APP 应降速。

## 5. 文件传输流程

### 5.0 传输与升级互斥

**音源文件传输**（§4.5）与**固件升级**（§4.6）在同一 BLE 连接上**互斥**，同一时刻仅允许其中一路处于活跃状态。

**活跃状态定义：**

| 任务     | 活跃区间                                                                                          | 通道 / 命令             |
| ------ | --------------------------------------------------------------------------------------------- | ------------------- |
| 音源文件传输 | 自 CmdID `0x50` 返回 `Result=0x00` 起，至 `0x51` 成功、`0x54` 取消、连接断开，或 `0x51` 校验失败且设备已释放该 FileID 缓冲为止 | `0xAB01` / `0xAB03` |
| 固件升级   | 自 UpCmd `0x81` 握手成功起，至 UpCmd `0x41` 应答、连接断开，或 APP 在 UpCmd `0x82` 后终止流程为止                      | GATT `0xAC00`（§4.6） |

**互斥规则：**

| 场景                      | 规则                                              |
| ----------------------- | ----------------------------------------------- |
| 传输进行中 + 再次 CmdID `0x50` | **禁止**；须先 `0x51` 或 `0x54` 结束；设备返回 `Result=0x02` |
| 传输进行中 + UpCmd `0x80`    | **禁止**；设备回复 UpCmd `0x82`                        |
| 升级进行中 + CmdID `0x50`    | **禁止**；设备返回 `Result=0x02`                       |
| 升级进行中 + UpCmd `0x80`    | **禁止**（已有升级会话）                                  |
| 播放进行中 + 传输或升级           | **允许**；不因播放拒绝 `0x50` 或 UpCmd `0x80`             |

**APP 规则：**

1. **禁止**在音源传输进行中再次发送 CmdID `0x50`；须先 `0x51` 结束或 `0x54` 取消。
2. 传输进行中，APP 仍可对**当前 FileID** 执行 `0x52` 查窗口、向 `0xAB03` 写分片。
3. **禁止**在固件升级活跃区间内发起音源传输；升级前须确保无进行中的传输。
4. **禁止**在音源传输活跃区间内发起固件升级（UpCmd `0x80`）。
5. 低电量（<20%）场景下，APP 不应发起传输或升级（见 §7.2）。

**设备规则：**

1. 传输进行中须拒绝新的 CmdID `0x50` 与 UpCmd `0x80`，分别返回 `Result=0x02` 与 UpCmd `0x82`。
2. 升级进行中须拒绝 CmdID `0x50`，返回 `Result=0x02`。

文件传输采用分包 + 窗口确认机制，兼顾吞吐量和可靠性。完整流程分为以下 6 个阶段：

| 阶段  | 步骤   | 说明                                                                                                           |
| --- | ---- | ------------------------------------------------------------------------------------------------------------ |
| ①   | 握手   | APP 发送 `0x50`，附带 FileID、MusicID、FileSize。设备返回 `0x00`（同意）、`0x02`（已有传输，见 §5.0）或 `0x03`（空间不足）。可先 `0x40` 查询剩余空间。 |
| ②   | 分包传输 | 按 §5.2 计算包数，逐包 Write `0xAB03`；PacketIndex 从 0 递增。                                                            |
| ③   | 窗口确认 | 每发满 128 包或进入新窗口前，发送 `0x52`；根据 `0x53` Bitmap 重传 bit=0 的包。末窗口规则见 §5.2。                                         |
| ④   | 结束   | 全部包确认后发送 `0x51`（全文件 XOR）。设备 `Result=0x00` 后落盘；并可能 Notify `0xE5`。                                             |
| ⑤   | 取消   | 用户中止或重传失败时发送 `0x54`；设备 Notify `0xE6`（可选）。                                                                    |
| ⑥   | 异常   | 握手 `0x03` 提示清理空间；校验失败 `0x51` 返回 `0x03`。                                                                      |

### 5.1 传输时序图（含可直接使用的 hex）

场景：`.mp3` 文件 **62464** 字节，MTU=247，**PayloadMax=238**，包数 **N=263**（PacketIndex 0 ~ 262）；窗口 0（0 ~ 127）、窗口 1（128 ~ 255）、窗口 2（256~ 262，末窗口）；`FileID=1`，`MusicID=100`。

| 步骤  | 方向     | 说明                          | 示例 hex                                                                   |
| --- | ------ | --------------------------- | ------------------------------------------------------------------------ |
| 1   | APP→设备 | 传输开始 `0x50`                 | `A5 5A 50 20 09 01 64 00 00 00 00 F4 00 00 17`                           |
| 2   | 设备→APP | 应答同意                        | `A5 5A 00 20 50 00 8F`                                                   |
| 3   | APP→设备 | 发包 0~127 → `0xAB03`         | 每包：`A5 5A 00 [Index LE] [≤238B Payload] [Checksum]`                      |
| 4   | APP→设备 | 查窗口 0 `0x52`                | `A5 5A 52 21 03 01 00 00 8E`                                             |
| 5   | 设备→APP | 窗口应答 `0x53`                 | `A5 5A 00 21 53 00 01 00 00 FF×16 8C`（全收齐示例）                             |
| 6   | APP→设备 | 按 Bitmap 重传丢包               | 仅重发 bit=0 的 PacketIndex                                                  |
| 7   | APP→设备 | 发包 128~255                  | `A5 5A 00 80 00 [Payload] [Chk]` … `A5 5A 00 FF 00 [Payload] [Chk]`      |
| 8   | APP→设备 | 查窗口 128 `0x52`              | `A5 5A 52 22 03 01 80 00 0D`                                             |
| 9   | 设备→APP | 窗口应答                        | `A5 5A 00 22 53 00 01 80 00 FF×16 0F`（全收齐示例）                             |
| 10  | APP→设备 | 发包 256~262（末包 Payload=108B） | `A5 5A 00 00 01 [Payload] [Chk]` … `A5 5A 00 06 01 [108B Payload] [Chk]` |
| 11  | APP→设备 | 查窗口 256 `0x52`              | `A5 5A 52 23 03 01 00 01 8D`                                             |
| 12  | 设备→APP | 末窗口应答（bit0~6=1，其余忽略）        | `A5 5A 00 23 53 00 01 00 01 7F 00×15 F0`                                 |
| 13  | APP→设备 | 结束 `0x51`                   | `A5 5A 51 24 02 01 XX [Checksum]`（`XX`=全文件 XOR）                          |
| 14  | 设备→APP | 保存成功                        | `A5 5A 00 24 51 00 8A`                                                   |
| 15  | 设备→APP | 事件（可选）                      | `A5 5A 01 FF E5 06 01 64 00 00 00 00 87`                                 |

**包数验算：** `262×238 + 108 = 62464`；末包 PacketIndex=262，Payload 长度 108 字节。

### 5.2 分包、Bitmap 与末窗口规则

#### 包数与末包

```text
PayloadMax = ATT_MTU - 9        // MTU=247 → 238
PacketCount N = ⌈FileSize / PayloadMax⌉
末包 Payload 长度 = FileSize - (N-1) × PayloadMax   // 1 ≤ 长度 ≤ PayloadMax
```

- 仅 **PacketIndex = 0 .. N-1** 有效；`PacketIndex ≥ N` 的写入设备应忽略。
- 末包 **禁止** 用 0x00 等填充至 PayloadMax；XOR 校验仅对文件原始字节计算。

#### Bitmap 位序（128 bit / 16 字节）

对窗口内偏移 `k`（0≤k≤127），对应包序号 `PacketIndex = WindowBase + k`：

| 项    | 规则                                          |
| ---- | ------------------------------------------- |
| 字节索引 | `byteIndex = k / 8`（Bitmap 第 0 字节对应 k=0~7）  |
| 位索引  | `bitIndex = k % 8`（**bit0 为 LSB**）          |
| 已收到  | `Bitmap[byteIndex]` 的 bit`bitIndex` = **1** |
| 未收到  | 对应 bit = **0**，APP 须重传该 PacketIndex         |

示例：WindowBase=0，仅包 0、2 未收到 → `Bitmap[0] = 0b11110101`（0xF5），其余字节 0xFF。

#### 末窗口规则

设 `LastWindowBase = (N - 1) / 128 * 128`（向下取整到 128 的倍数）。

| 规则    | 说明                                                                        |
| ----- | ------------------------------------------------------------------------- |
| 有效位范围 | 仅 `k` 满足 `WindowBase + k < N` 的 bit 有意义                                   |
| 无效位   | `WindowBase + k ≥ N` 的 bit **必须为 0**（设备不得置 1；APP 忽略为 1 的情况）               |
| 查询时机  | 发送完该窗口内最后一个包（PacketIndex = N-1）后，再发 `0x52` 查询 `WindowBase=LastWindowBase` |
| 通过条件  | 末窗口内所有有效 bit 均为 1 后，方可发送 `0x51`                                           |

**示例：N=263，末窗口 WindowBase=256，有效 k=0~6（对应包 256~262）**

- 7 个有效 bit 均为 1 时，Bitmap 第 0 字节为 `0x7F`（`01111111`），字节 1~15 均为 `0x00`。

## 6. 结果码与事件码

### 6.1 应答结果码（Result）

| 值    | 含义    | 说明及处理建议                                               |
| ---- | ----- | ----------------------------------------------------- |
| 0x00 | 成功    | 命令执行正确，无需特殊处理                                         |
| 0x01 | 无效参数  | 参数越界或格式错误，APP 应检查参数范围后重试                              |
| 0x02 | 设备忙   | 设备正在处理其他任务（含文件传输进行中拒绝二次 `0x50`），APP 可等待 500ms 后重发同一命令 |
| 0x03 | 文件错误  | 文件传输失败（CRC/XOR 错误、SD 卡写入失败、存储空间不足等），APP 应提示用户并重新传输    |
| 0x04 | 不支持   | 未识别的命令码或固件版本不支持，APP 应检查协议版本兼容性                        |
| 0x05 | 数据不存在 | 查询的 AlarmID / MusicID 不存在，或取消传输时 FileID 无进行中任务        |

### 6.2 事件码（EventID）

事件码用于设备主动通知 APP 的事件通知帧（RspType=0x01）。与命令应答不同，事件帧无 Seq，APP 应异步处理。

| 事件码  | 事件名称     | 附加数据格式                                | 说明                                        |
| ---- | -------- | ------------------------------------- | ----------------------------------------- |
| 0xE1 | 闹钟触发     | 见下方「闹钟事件负载」                           | 闹钟在预设时间触发                                 |
| 0xE2 | 闹钟超时停止   | 见下方「闹钟事件负载」                           | 响铃超时，设备自动停止                               |
| 0xE3 | 用户手动停止   | 见下方「闹钟事件负载」                           | 用户按键停止闹钟                                  |
| 0xE5 | 文件传输完成   | FileID(1B) + MusicID(4B) + Status(1B) | Status：0x00=落盘成功；0x01=XOR 校验失败            |
| 0xE6 | 文件传输取消   | FileID(1B) + Reason(1B)               | Reason：0x00=APP 发送取消；0x01=设备超时/内部错误       |
| 0xE7 | 来电提醒状态变更 | Action(1B)                            | `0x01`=已开始播放来电铃音；`0x00`=已停止               |
| 0xE8 | 恢复出厂重启   | 无（DataLen=0）                          | 设备将在约 3 秒内重启（0x31 成功后）                    |
| 0xEB | 免打扰状态变更  | Enable(1B)                            | `0x01`=已开启；`0x00`=已关闭；APP 应收 `0x25` 同步 UI |

**闹钟事件负载：**

| AlarmType   | DataLen | 格式                                                                                  |
| ----------- | ------- | ----------------------------------------------------------------------------------- |
| `0x00` 例程   | 3       | AlarmType(1B) + AlarmID(1B) + Phase(1B)，Phase 取值与 §4.1 命令 `0x07` 一致（`0x00`~ `0x04`） |
| `0x01` 其他闹钟 | 3       | AlarmType(1B) + AlarmID(1B) + Phase(1B)：`0x00`=激活期，`0x01`=唤醒期                       |

**示例：例程起床唤醒期触发（EventID=0xE1，AlarmID=1，Phase=唤醒期）**

`A5 5A 01 FF E1 03 00 01 03 E1`

| 偏移  | 字节      | 解析           |
| --- | ------- | ------------ |
| 0~1 | `A5 5A` | 帧头           |
| 2   | `01`    | RspType=事件帧  |
| 3   | `FF`    | 固定           |
| 4   | `E1`    | 闹钟触发         |
| 5   | `03`    | DataLen=3    |
| 6   | `00`    | AlarmType=例程 |
| 7   | `01`    | AlarmID=1    |
| 8   | `03`    | Phase=起床唤醒期  |
| 9   | `E1`    | Checksum     |

## 7. 设备主动上报

### 7.1 电源状态上报

KL252 通过电池服务（UUID `0x180F`）提供两级电源信息：**标准电量**（`0x2A19`）与 **电源状态**（`0xFF01`）。APP 应以 `0xFF01` 作为 UI 展示与业务逻辑的主数据源；`0x2A19` 保留为标准 BLE 兼容通道。

#### 7.1.1 标准电量（0x2A19）

| 属性      | 说明                                        |
| ------- | ----------------------------------------- |
| 特征 UUID | `0x2A19`（Battery Level）                   |
| 数据格式    | 1 字节，`0x00`~ `0x64`（0%~100%）              |
| 上报触发条件  | 电量变化 ≥ 1% 时主动 Notify；APP 也可主动 Read 获取当前电量 |
| 上报频率    | 非文件传输模式下最多每 60 秒上报一次；音源传输及固件升级期间暂停上报      |

**示例：设备上报电量 85%：** `55`（单字节，无 `A5 5A` 封装）

#### 7.1.2 电源状态（0xFF01，APP 主通道）

厂商自定义特征，固定 **2 字节** 负载，无 `A5 5A` 帧封装。APP 连接后须订阅 CCCD，并优先通过本特征获取电量与充电状态。

| 字节     | 字段            | 长度   | 类型    | 说明                                      |
| ------ | ------------- | ---- | ----- | --------------------------------------- |
| Byte 0 | BatteryLevel  | 1 字节 | uint8 | 电量百分比，`0x00`~ `0x64`（0%~100%），与 `0x2A19` 数值一致 |
| Byte 1 | ChargeState   | 1 字节 | uint8 | 充电状态，取值见下表                              |

**ChargeState 取值：**

| 值      | 含义   | 说明                |
| ------ | ---- | ----------------- |
| `0x00` | 未充电  | 设备由电池供电，未接入充电器    |
| `0x01` | 充电中  | 已接入充电器，电池正在充电     |
| `0x02` | 已充满  | 已接入充电器，电池已充满不再充电  |

| 属性      | 说明                                                                 |
| ------- | ------------------------------------------------------------------ |
| 特征 UUID | `0xFF01`（Power Status）                                             |
| 上报触发条件  | ① 电量变化 ≥ 1%；② **充电状态变化**（插拔充电器、从未充满变为已充满）；APP 也可主动 Read |
| 上报频率    | 与 §7.1.1 相同；充电状态变化时**立即** Notify，不受 60 秒节流限制                    |
| 一致性要求   | 每次 Notify / Read 的 `BatteryLevel` 须与当前 `0x2A19` 读值一致；状态变化时两特征应同步更新 |

**示例：**

| 场景        | 十六进制   | 解析              |
| --------- | ------ | --------------- |
| 85%，未充电    | `55 00` | Level=85%，未充电   |
| 85%，充电中    | `55 01` | Level=85%，充电中   |
| 100%，已充满   | `64 02` | Level=100%，已充满  |

### 7.2 连接与断开建议

| 场景       | 建议处理                                                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 连接成功后    | ① 订阅 0xAB02 / 0x2A19 / **0xFF01** CCCD；② Read `0xFF01` 获取当前电源状态；③ 协商 MTU≥247；④ 时间同步（0x20）；⑤ 查询固件版本（0x30）；⑥ 建议查询 0x05/0x06/0x07/0x25；⑦ 可选 0x21/0x22/0x23、0x40/0x41/0x46；⑧ 固件升级前另订阅 0xAC02 CCCD |
| 连接断开时    | 清空未完成命令队列；传输中断时记录 WindowBase 与 PacketCount，但 **不支持断点续传**（须重发 `0x50`）                                                                                    |
| 重连后      | 重新订阅 CCCD（含 `0xFF01`）、Read `0xFF01` 刷新电源状态、同步时间（含年月日）；音源传输须从 `0x50` 重新开始；固件升级须从 UpCmd `0x80` 重新开始                                                              |
| 文件传输中    | **禁止**再次发送 CmdID `0x50` 或发起固件升级；须 `0x51`/`0x54` 结束传输后再操作（§5.0）                                                                                          |
| 固件升级中    | **禁止** CmdID `0x50`；须等待 UpCmd `0x41` 或断连后再发起传输（§5.0）；播放可继续                                                                                              |
| 电量低于 20% | APP 提示用户为设备充电，暂停音源传输及固件升级                                                                                                                               |

## 8. 附录

### 8.1 AlarmID 与 MusicID 字段说明

AlarmID 采用 1 字节无符号整数（uint8）；MusicID 采用 4 字节无符号整数（uint32，小端字节序）。具体规则如下：

| 字段      | 长度            | 范围           | 说明               |
| ------- | ------------- | ------------ | ---------------- |

### 8.2 WeekMask 位定义

| bit7 | bit6 | bit5 | bit4 | bit3 | bit2 | bit1 | bit0 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| 从不模式 | 周六   | 周五   | 周四   | 周三   | 周二   | 周一   | 周日   |

**编码规则：**

| WeekMask       | 含义                                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------- |
| `0x80`         | **从不**（单次执行）：bit7=1 且 bit0~bit6=0；在匹配的时刻触发**一次**后，设备将该调度块的 WeekMask 自动置为 `0x00`（已执行，不再重复），或由固件内部标记「已响」直至 APP 下次修改该条目 |
| `0x01`~ `0x7F` | **按星期重复**：bit7=0；至少置位一个 bit0~bit6（例程至少选一天；其他闹钟可不选星期而使用 `0x80`）                                                       |
| `0x00`         | **无效/已执行**：不应作为新建条目的周期；查询已执行的「从不」条目时可能见到                                                                             |

示例：

- `0x7F`（0111 1111）= 每天（bit7=0）
- `0x3E`（0011 1110）= 周一至周五
- `0x41`（0100 0001）= 仅周日和周六
- `0x80`（1000 0000）= 从不，仅响一次
